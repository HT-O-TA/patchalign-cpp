# PatchAlign-Cpp 最终实验报告

## 摘要

PatchAlign-Cpp 建立了一条面向 C/C++ 程序修复的完整模型对齐链：统一数据契约、隔离切分、LoRA/QLoRA SFT、沙箱执行评分、真实执行偏好数据、DPO、消融和冻结交付。

最终选择 **M1-R2（NF4 QLoRA SFT）** 作为默认模型。DPO-beta0.3 在正式集上取得更高 Pass，但因超时率超过预设门禁而不晋级。确认集和外部 Defects4C 结果显示，当前系统的主要瓶颈已从补丁格式与编译能力转向跨分布语义修复。

## 1. 实验对象

- Base：Qwen2.5-Coder-7B。
- 数据来源：CommitPackFT、RunBugRun；外部评测使用 Defects4C。
- 训练路线：BF16 LoRA、NF4 QLoRA、DPO。
- 默认 SFT：M1-R2。
- 最佳 DPO：beta=0.3。

所有对比使用冻结的数据清单、提示模板、生成参数、沙箱限制和评分协议。模型权重、大规模数据与推理结果不进入 Git 仓库。

## 2. 评分协议

每个生成结果依次经过：

1. 输出与统一 diff 解析；
2. 补丁应用；
3. 编译；
4. 公开、隐藏及回归测试；
5. 时间与资源限制检查。

严格 Pass 是主指标；Apply、Compile、测试失败类型和 Timeout 用于解释模型行为。训练 loss 和文本相似度不作为程序正确性的替代指标。

## 3. 数据与隔离

数据经过字段标准化、许可证检查、缺失与异常过滤、长度限制、去重和固定种子的分层抽样。RunBugRun 保留上游 split，CommitPackFT 按仓库家族隔离，避免同一项目家族直接跨入训练和验证/测试集合。

这些措施降低了可观测的直接泄漏风险，但不能证明 Base 的预训练语料中没有见过相同或相近代码。因此外部集成绩被单独报告，并对泛化结论保持保守。

## 4. SFT 结果

| 模型 | Pass | Apply | Compile | Timeout |
|---|---:|---:|---:|---:|
| M0 Base | 0/500 | 0 | 0 | 0 |
| M1 | 15/500 | 391 | 373 | 3 |
| M1-R2 | 14/500 | 412 | 392 | 2 |

SFT 极大改善了输出格式、补丁应用和编译能力。M1-R2 的 Pass 比 M1 少 1 条，但 Apply 增加 21、Compile 增加 19、Timeout 减少 1，因此被选为更稳定的后续基线。

BF16 LoRA 与 NF4 QLoRA 的 pilot 用于评估精度、显存和训练稳定性的取舍。二者均为 1/70 Pass，未显示可宣称的质量差异；NF4 的完整 pipeline 峰值显存更低，因此按预注册资源平局规则进入正式训练。这是一项受当前模型、数据和集群条件约束的工程结论。

## 5. DPO 结果与门禁

偏好对由候选补丁的真实执行结果构造，优先使用补丁应用、编译、测试和回归关系，而不是文本风格评分。

| 模型 | Pass | Apply | Compile | Timeout | 正式结论 |
|---|---:|---:|---:|---:|---|
| M1-R2 | 14/500 | 412 | 392 | 2 | 默认模型 |
| DPO-beta0.3 | 19/500 | 437 | 424 | 5 | 不晋级 |

DPO-beta0.3 的 Pass 增加 5，Apply 增加 25，Compile 增加 32；但 Timeout 从 0.4% 增至 1.0%，增加 0.6 个百分点，超过门禁允许的 0.5 个百分点。因此项目没有以单一最高 Pass 取代综合稳定性决策。

## 6. 泛化评测

| 模型 | 确认集（124） | Defects4C（176） |
|---|---:|---:|
| M1-R2 | 0 | 1 |
| DPO-beta0.3 | 0 | 1 |

两种模型在外部分布上没有形成显著差异。正式集提升不能外推为通用修复能力；DPO 主要改善了当前分布中的生成与编译行为，没有突破跨项目语义泛化瓶颈。

## 7. 消融与失败分析

项目对数据、提示、解码和 DPO 强度进行了受控比较。总体观察是：

- 训练和模板优化首先改善补丁格式、应用率和编译率。
- 更激进的解码或偏好优化可能增加候选多样性，也可能提高超时和不稳定行为。
- 正确补丁仍受故障定位、项目上下文、构建依赖和测试信号不足限制。
- 确认集与 Defects4C 是当前最重要的负面证据，不能由正式集提升掩盖。

## 9. 局限与后续方向

- 绝对 Pass 率较低，不能宣称已解决通用 C/C++ 自动修复。
- 数据来源和任务形态有限，项目级上下文不足。
- 仓库级隔离不能排除 Base 预训练污染。
- 外部集结果说明分布迁移仍是核心难题。
- 后续应优先扩充可执行仓库任务、强化近重复审计、增加失败测试与项目上下文，并在更宽的开发分布上选择对齐超参数。
