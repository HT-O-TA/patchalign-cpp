# ADR-0007：A4 可执行候选池可行性修正

状态：Accepted implementation correction
日期：2026-09-06

## 背景

A4 首次 CPU 数据 Job `95574` 在全量 243 项测试通过后，于候选构建阶段按 fail-closed 规则退出。冻结配置要求从 A3.3 train-only RunBugRun 数据中准备 27 个 `file_window` 备用候选，同时构建器要求每个候选至少具有 5 条上游测试。

对冻结输入做只读全量审计后确认：27 个 `file_window` 训练样本中只有 26 个达到至少 5 条测试；唯一不满足者为 problem `p04013`，只有 4 条测试。因此“27 个候选且每个至少 5 条测试”在固定输入上不可同时满足。function 样本中有 2,571 个达到该门槛，足以提供原定 600 个候选。

## 决策

1. 保留每个 A4 可执行候选至少 5 条测试的质量门槛，不纳入 `p04013`，不通过降低门槛使失败配置勉强运行。
2. `file_window` 备用候选池从 27 修正为可实现的 26；function 备用候选池仍为 600。
3. 最终资格目标保持 `256 function + 8 file_window = 264`，候选生成仍为每条 4 个，共 1,056 个；训练来源、split、family 唯一性、token 上限、双重回放和隔离规则均不变。
4. 候选排序仍由冻结 seed 与 sample ID 的 SHA256 决定，但先按“至少 5 条测试”过滤，再在各任务层内排序。
5. 首次失败 Job `95574` 与失效依赖 Job `95575` 必须保留在执行记录；部分候选目录移动归档，不作为有效 A4 输入。

## 解释边界

这是在任何候选资格结果或模型输出产生前发现的输入可行性矛盾修正，不是观察质量结果后的阈值放宽。修正减少 1 个备用候选，但不改变最终数据规模、组成或质量门槛。
